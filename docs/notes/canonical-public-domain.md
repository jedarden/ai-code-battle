# Canonical Public Domain Decision

**Decision Date:** 2026-08-21  
**Bead:** aicodeba-ee0426a0  
**Status:** IMPLEMENTED

## Problem

The domain `aicodebattle.com` is NXDOMAIN (not registered), but documentation and code referenced it as the primary public domain. The deployed site is only reachable at `ai-code-battle.pages.dev`.

## Investigation

Verified DNS status:
```bash
dig aicodebattle.com  # Returns NXDOMAIN
curl -I https://ai-code-battle.pages.dev  # HTTP 200
```

Files containing `aicodebattle.com` references:
- `web/index.html` (lines 10, 13, 17, 20) - OpenGraph and Twitter meta tags
- `web/pages.json` (line 5) - Domains configuration
- `docs/plan/plan.md` - Already uses `ai-code-battle.pages.dev` correctly
- `web/src/og-tags.ts` - Already uses `ai-code-battle.pages.dev` correctly
- `web/src/pages/` - No user-facing absolute URL references

The `b2.aicodebattle.com` CDN host referenced in planning docs is no longer needed — replays are now served through the Pages Function at `web/functions/r2/[[path]].ts` from an R2 binding.

## Decision

**Option (b): Standardize on `ai-code-battle.pages.dev` as the canonical public domain everywhere user-facing.**

Rationale:
- Domain registration requires manual action and payment — blocked for automated resolution
- The Pages deployment already works correctly at `ai-code-battle.pages.dev`
- All runtime code (og-tags.ts, clip-maker.ts) already uses the Pages origin
- Only static HTML meta tags needed updating

## Changes Made

### 1. web/index.html
Updated OpenGraph and Twitter meta tags to use `ai-code-battle.pages.dev`:
- `og:url` → `https://ai-code-battle.pages.dev/`
- `og:image` → `https://ai-code-battle.pages.dev/img/og-default.png`
- `twitter:url` → `https://ai-code-battle.pages.dev/`
- `twitter:image` → `https://ai-code-battle.pages.dev/img/og-default.png`

### 2. web/pages.json
Updated domains array from `["aicodebattle.com"]` to `["ai-code-battle.pages.dev"]`

### 3. Already Correct (No Changes Needed)
- `web/src/og-tags.ts` - Runtime OG tag generation already uses Pages domain
- `docs/plan/plan.md` - Documentation already references Pages domain
- `web/src/pages/clip-maker.ts` - Share functionality uses relative URLs and `window.location`

## Acceptance Criteria

✅ Every user-facing absolute URL emitted by `web/src` now resolves in a browser:
- OpenGraph tags in `web/index.html` point to `ai-code-battle.pages.dev`
- Dynamic OG tags generated by `og-tags.ts` use `ai-code-battle.pages.dev`
- Share links use `window.location.origin` (resolves to current domain)
