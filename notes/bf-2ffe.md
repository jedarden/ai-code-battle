## Source Identified

The secret `acb-app-credentials-acb-app` is **automatically generated by CloudNativePG** when Database resources are created.

## Details

**CNPG Cluster**: `cnpg-apexalgo` in namespace `cnpg`
- Definition: `declarative-config/k8s/apexalgo-iad/cnpg/postgres.yml`
- Instances: 3
- Storage: local-path (ephemeral, node-local)

**Database Resource**: `ai_code_battle`
- Definition: `declarative-config/k8s/apexalgo-iad/cnpg/database-ai-code-battle.yml`
- Owner: `postgres`
- Cluster: `cnpg-apexalgo`

**Expected CNPG Behavior**:
When a Database resource is created, CNPG automatically generates a connection secret with the pattern:
- Name: `<cluster-name>-app-credentials-<database-name>`
- For this case: `cnpg-apexalgo-app-credentials-ai-code-battle`

**Discrepancy Found**:
- Deployment expects: `acb-app-credentials-acb-app`
- CNPG would generate: `cnpg-apexalgo-app-credentials-ai-code-battle`
- These names don't match

1. The secret is **not** defined in `declarative-config` as a SealedSecret, ExternalSecret, or manual Secret
2. The secret exists on the live cluster (123 days old, 8 keys) per `bf-wsf.md`
3. The secret name mismatch suggests either:
   - Manual creation with custom name

Verify the actual secret name on the cluster and either:
1. Update deployments to use the CNPG-generated secret name, or
2. Ensure the database is configured to generate the expected secret name
